# PRORES.NLB — ProRes 422 / LT / Proxy 行，装在相机自己的菜单里

NLoader 常驻扩展（resource extension，min_abi 5，ABI ≥5 的 loader 都能加载），
Z 6III 固件 **C 2.00** 专用。构建：`sh build.sh <新的输出目录>`（用这个仓库的 SDK 和 `nloader` 工具）。

## 它做什么

1. **视频拍摄菜单**，在"视频品质(N-RAW)"后面插一行：

       Video quality (ProRes)        HQ / 422 / LT / PROXY

   进去是四行的子页（HQ、422、LT、Proxy），光标停在当前档上。
   右边的值只在"视频文件类型 = ProRes 422 HQ 10位(MOV)"时显示，其它文件类型留空
   （和原生"视频品质(N-RAW)"行在非 N-RAW 时留空是一个做法）。

2. 选中的档位同时改掉：录制服务的 hardware type、码率表（按 Apple 的
   220:147:102:45 缩放）、MOV 里的 FourCC（apch/apcn/apcs/apco）和编码器名、
   回放时接受的 FourCC、拍摄界面显示的 CODEC 名。

档位存在相机设置区的一个空闲填充字节里（0xA03F0AEF5，紧跟 item 0x0F0B
WbMovieSameStill；后面那个 0xA03F0AEF6 归 HERAW）。读写的都是 **A 库**那一份（库间距
0x2B0），和 Z8 补丁一样：切换拍摄菜单库不会换掉这个设置。

HSFC 的 HE RAW（预拍/高速连拍存 NEF）是另一个扩展，见 `../heraw`。两个可以同时开机加载
（`NLOADER/ENABLED` 一行一个 id：`prores`、`heraw`）。

## 不适用于 Z 8（2026-10-17 核对）

这个程序按地址修改 Z 6III 2.00 固件的录制服务和菜单页（`z63fw.h`：那版固件的地址、原厂字节和
编码器布局），这些在 Z 8 3.11 上都没有研究过，它的编码器和菜单也不一样；Z 8 的 profile 也没有
声明可以代替它们的 named hook 或表。所以 `prores.json` 的 `models` 保持 `z6iii/2.00`：
Z 8 上 loader 把它灰显为“其他机型”，从不加载。

## 做法：没有常驻代码跑在相机的路径上

菜单引擎建页时读的东西全部由 .data 里的页记录指出来：元素表、44 字节的行记录、
每行一张事件表、行数；行是按 item id 找的，不是按下标，所以中间插一行不影响任何
原有行（NLoader `research/menus.md`）。处理函数也只是 .data 里的五个函数指针。
所以菜单部分**一条指令都不用改**：

- 45 条原行记录 + 我们的一行、46 个事件表指针，拷进插件自己的内存块，页记录指过去；
- 子页复用 N-RAW 画质页的窗口 0x119：我们这行的事件动作在跳转前把 0x119 的页记录
  换成四行那份，N-RAW 那行的动作（它的事件表也克隆过）换回原来的。一个窗口两个页；
- 包了两个 .data 回调：视频菜单的刷新（写我们那行的值）、0x119 的 entry（标题 + 单选点）。
  都先调原函数。

编码器那边**只有六处单字补丁，而且全是"改一个地址常量"，没有任何跳转/detour**：

| 位置 | 改成 |
|---|---|
| 0x40D229F4 / FC | hardware type 从我们的设置字节读（MOVZ/MOVK 改两个半字） |
| 0x40D22A14 / A1C | `LDR`→`LDRB`，`CMP #2`→`CMP #4`（放行 0..3） |
| 0x40D223BC/C0、0x40D22540 | 码率表指向插件的副本 |
| 0x405198C0 | CODEC 名表指向插件的副本（第 4 项指向我们的字符串） |
| 0x40CEFD10 | sample description 模板指向插件的副本（FourCC/名字已经填好） |
| 0x40CEB320 | 回放比较 FourCC 的高 24 位，四档都认 |

每一处都是一次 ≤64 字节、不跨 cache line 的原子写（NLoader `code_patch`）。
ProRes RAW 的分支原样不动（它读的还是原来那个 .data 字，值仍是 0）。

插件的表放在 `mem_alloc` 的一个 9 KB 块里。常驻扩展只要有一个可写静态变量就会多占
一个 2 MiB 块（GYROLOG 的教训），所以插件不保存指针：唯一需要用到块地址的回调，
通过固件 .data 里的"视频页记录 → 行记录数组"找回来（块的第一段就是那个数组）。

> 早期版本把这些表放在固件代码段末尾的零区（0x4090E898..0x40C00000），结果在
> **把程序打包进固件的那种 loader 构建上（`[services.platform.bundle]` 从 0x4090E8C0 起）
> 整段是占用的**，插件只能拒装，日志写 `the code cave is in use`。现在不再依赖那段。

## 安全措施

- 每个要改的位置都记着编译时的原指令字，`codec_fingerprint()` / `menu_fingerprint()`
  全部核对通过才动手；不对就什么都不写，返回 0（返回非零会占住 NLoader 的中断标记）。
- 页记录必须还指着原厂数组、行数还是 45/2 —— 也就是说没被别的东西改过、也没装过一遍。
- 菜单用的 7 个 runtime text slot（252..258）要先确认有缓冲区，否则写文本会拷到地址 0；
  没有就只装编码器那半边。
- 新行的 item id（0x317D/0x3CD5/0x3CD7/0x3CD9/0x3CEB）取自：引擎按 id 记可见性的
  范围内（0x2988..0x4DAF）、没有任何原生行记录用、而且整个镜像里没有任何指令立即数
  或对齐的 32 位字提到过它们。克隆的事件表里"加入我的菜单"那条记录用一个永远拒绝的
  guard 关掉了。
- 只有一种情况返回非零：六处补丁写到一半失败（相机需要关机重开）。
- 分配到的块如果高 16 位不为 0（这台机器不会）就拒装，因为补丁只改地址的三个半字。

## QEMU 验证（fw-plat18，2026-10-17）

- 视频菜单里"视频品质(N-RAW)"下面出现 **Video quality (ProRes)**，> 标记正常；
- 子页四行、标题正确、光标停在已选档；选 LT 后退回，行右边显示 **LT**；
- 把视频文件类型改成 ProRes 422 HQ 10位(MOV) 后，行右边立刻显示 **HQ**（文件类型判定正确）；
- 其余原生行、导航、返回都没受影响。

**掉电保存在 QEMU 里测不了**：把一个原厂设置（视频品质(N-RAW) 改成 NORM）和我们的档位
一起设好，等相机待机断电，再用同一份 snor.bin 重启 —— 两个都回到了默认值。连原厂设置都没保住，
说明模拟器这条路根本没把设置区写回 SNOR，所以这个实验对我们的字节什么也证明不了。
只能在机身上验：设好档位 + 改一个原厂设置当对照 → 电源开关关机 → 开机 → 看两个还在不在。

其余未验证：实际录制（QEMU 没有编码器模型）。机身上验证过的见下面"已知限制"里的 LT 录制。

## 已知限制

- 设置库 A→B 复制时不会带上这个字节（Z8 补丁改了 0x41007404 那处，这里没做）。
- 文件类型菜单里仍然写"ProRes 422 HQ 10位(MOV)"（字符串在 rodata，NLB 改不了）。
- 行标签是英文（ASCII）：runtime text slot 只能写单字节文本，中文要走重打包改字符串表。
- ~~0..3 = HQ/422/LT/Proxy 是推断~~ **2026-10-17 机身验证通过**：选 LT 录 4K 29.97p，
  ffprobe 得 `codec_tag_string=apcs`、码率 422.8 Mb/s（HQ 档该是约 1028 Mb/s，
  LT 目标 454 Mibit/s ≈ 476 Mb/s，实测 89% 属正常）。FourCC 补丁和码率表补丁都生效了。
  还要看的：画面有没有问题、相机内回放、CompressorName。
- 以后可以把这些点注册进 loader profile 的 `[named.*]`，改成 ABI 8 的 `hook_attach` /
  `table_write` 写法（那样地址和指纹由 loader 管，但每改一个地址都要重刷 loader）。
